# 让 AI 帮你适配这台电脑

把源码目录交给具备文件读取能力的 AI，并发送：

> 请先读取本项目 README.md、AGENTS.md、docs/AI_SETUP.md 和 docs/ROADMAP.md，帮我在当前电脑的 DeepSeek Harness 中安装并配置这个插件。先自行检查环境，只询问缺少的必要信息；使用我自己的模型渠道，保留已有配置和历史。先完成最小可运行验证，再讨论新增功能。

有些 AI 工具会自动读取 `AGENTS.md`，有些不会，因此上面的读取指令仍需明确发送。没有电脑操作工具的 AI 应提供当前环境适用的步骤，请用户反馈结果，不能假装已经执行。

若拿到的只是运行包、没有 `src`，先完成宿主配置和安装；修改功能前取得源码，不直接修改 `lib` 冒充源码改进。

## 1. 先检查，再问用户

能从电脑确认的信息不要重复询问：操作系统、源码位置、Harness 安装方式和版本、活动 profile、是否已有该插件，以及用户当前打开的服务。开发者再检查 Node/npm；普通使用者可以直接安装已有的 `lib`，不要求先装开发工具。

Windows 可通过可用命令和应用版本检查；其他系统使用对应工具。安装命令及目录根据检测结果选择，不照抄文档中的示例路径，不自动安装最新宿主覆盖现有版本。

只在无法确定时询问以下事项，一次最多 3 个：

1. **你实际使用 Harness 桌面版，还是 CLI/Web？哪个现有环境希望安装？**
2. **你准备使用哪个官方 API、中转站或 Coding Plan？想用哪些模型？** 不索取 Key 原文；让用户在自己的 Harness 设置中填写。
3. **这次先安装使用，还是修复一个具体问题？** 若需要迁移历史，再核实旧历史位置和希望保留的内容；默认保留。

用户已有明确答案时直接继续。操作目标是使用者的电脑，不是把作者的运行目录、测试 profile 或个人配置复制过去。

## 2. 配好宿主渠道，再选面板模型

| 用户的渠道 | AI 应采取的路径 |
|---|---|
| DeepSeek 官方 API | 优先检查 Harness 内置 DeepSeek 渠道，按宿主的模型设置填写用户自己的 Key；模型 ID 以当前官方目录为准。 |
| 智谱官方 API | 按智谱官方文档使用兼容接口，在 Harness 配置地址、协议和模型 ID；不要把国际站目录默认当作国内账户的配置。 |
| Wokey | 配置宿主渠道后使用现有「同步模型」；各栏及总结栏仍需选择实际存在的模型。 |
| 其他中转站 | 先核实官方说明的接口协议、地址和模型 ID，在 Harness 配置；本插件未为这些站点提供通用自动发现，必要时手动添加模型。 |
| Coding Plan / 套餐 | 先核实是否允许该客户端和用途，使用套餐规定的接口及模型；请求成功不等于必然计入套餐额度，查看平台用量记录。 |

通常改变 Harness 的渠道配置即可，不需要重写 Dashboard。协议不兼容时才调查宿主适配器；不要为了换地址在前端加入 API Key 或另建一套直连调用代码。

官方参考：[Harness 渠道配置](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/providers.md)、[DeepSeek API](https://api-docs.deepseek.com/)、[智谱兼容接口](https://docs.bigmodel.cn/cn/guide/develop/openai/introduction)。配置前核对当前文档，不固定沿用某个旧模型名称。

## 3. 安装并验证

1. 在用户实际使用的 Harness profile，通过插件管理安装当前源码目录或运行包并启用；本地目录链接安装后保留该目录。方法见 README。
2. 打开「多模型工作台」，手动为各栏和总结栏选择**用户已配置**的模型。默认 Wokey 路由不存在时不能直接发送。
3. 先确认界面能加载、能选模型。需要改代码时再安装开发依赖、构建及运行离线测试；离线通过不代替宿主中实际启用。
4. 按用户已授权的范围做最小真实验证：低成本模型的简短回答、并排两栏、指定模型总结；有合适任务时检查单路停止/重试。没有接口或测试额度，就把真实调用标成「待验证」。
5. 保存一条合成测试记录，关闭再打开确认能读回；已有旧历史先备份，不能为了制造空白环境清除真实记录。profile 无法识别时检查 README 中的数据目录回退规则。

Windows 是当前已有验证的平台；macOS/Linux 的源码适配路径可调查，但必须在对应系统实际运行后才能写成支持。不要为首次安装同时实施整个路线图。

## 4. 常见失败的检查顺序

| 现象 | 先查什么 |
|---|---|
| 侧边栏没有工作台 | 是否装在用户正在用的 profile、bundle 是否启用、`lib` 是否存在、宿主依赖是否匹配。 |
| 面板没有模型 | Harness 内是否已有可用渠道和模型；当前只对 Wokey 自动同步，其他渠道先手动配置。 |
| 一发送就失败 | 所选 provider/model 是否存在，官方地址与协议是否对应，Key/权限是否在宿主中配置正确；不读取或回显 Key。 |
| 回答为空或中断 | 区分推理尚未结束、输出额度用尽、网络 EOF 和上游错误；保留已收到的内容及真实失败状态。 |
| 历史突然变空 | 当前 profile 与旧版数据目录是否不同；先定位和备份，不能直接判定丢失或删除重建。 |

本机适配结果写入 Git 已忽略的 `ADAPTATION.local.md`，按四项简记：**环境与目标 / 修改内容 / 已通过与待验证 / 下一步**。不要把私有路径、凭证或原始聊天复制进公共 README。
